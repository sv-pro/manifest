# Authentication

Manifest has two authentication surfaces: **user sessions** (dashboard) and **agent API keys** (proxy).

## Guard Chain

Three global guards run on every request in this order:

```
Request
  │
  ▼
SessionGuard (auth/session.guard.ts)
  ├── @Public()? → skip all auth
  ├── Has valid Better Auth cookie? → attach user + session, continue
  └── No session → fall through to ApiKeyGuard
  ▼
ApiKeyGuard (common/guards/api-key.guard.ts)
  ├── Session already set? → skip
  ├── X-API-Key matches API_KEY env var? (timing-safe compare) → allow
  └── No match → 401
  ▼
ThrottlerGuard
  └── Rate limit: THROTTLE_LIMIT req / THROTTLE_TTL ms window
```

Mark any endpoint `@Public()` to bypass both session and API key checks (used for health, Better Auth routes, setup, public stats).

## User Sessions (Dashboard)

Better Auth handles login, registration, OAuth, and password reset at `ALL /api/auth/*`.

- **Instance**: `auth/auth.instance.ts` — `betterAuth()` with `emailAndPassword` plugin + 3 social providers (Google, GitHub, Discord). Each social provider only activates when both `CLIENT_ID` and `CLIENT_SECRET` env vars are set.
- **Database**: uses a `pg.Pool` instance passed directly (`betterAuth({ database: pool })`). Better Auth manages its own tables via `ctx.runMigrations()` — independent of TypeORM migrations.
- **Email**: Mailgun (via `MAILGUN_API_KEY` + `MAILGUN_DOMAIN`) for verification and password reset. If not configured, users are created but unverified.
- **Mounting**: Better Auth is mounted as raw Express middleware **before** `express.json()` because it needs body control. NestJS body parsing is re-added after.

### Auth Types

```typescript
// auth/auth.instance.ts
export type AuthSession = typeof auth.$Infer.Session;
export type AuthUser   = typeof auth.$Infer.Session.user;

// In controllers:
@Get('something')
async handler(@CurrentUser() user: AuthUser) {
  // user.id, user.name, user.email
}
```

## Agent API Keys (Proxy)

Agents authenticate to the LLM proxy using `mnfst_*` format bearer tokens.

- **Guard**: `AgentKeyAuthGuard` in `otlp/guards/agent-key-auth.guard.ts`
- **Storage**: `agent_api_keys` table; keys are hashed (scrypt KDF) at rest
- **Caching**: valid keys cached in-memory for 5 minutes to avoid repeated DB lookups
- **Self-hosted shortcut**: in `MANIFEST_MODE=selfhosted`, any non-`mnfst_*` token from loopback IPs (`127.x`, `::1`) is accepted without DB lookup — useful for local testing

### Key Format

`mnfst_<random>` — the prefix `mnfst_` identifies Manifest agent keys. Keys are generated by `ApiKeyGeneratorService.onboardAgent()` during first-use onboarding.

## Dashboard API Key

A separate `X-API-Key` header mechanism allows programmatic access to the dashboard API (e.g. for scripts). The key is the `API_KEY` environment variable, compared with `crypto.timingSafeEqual`.

## Social Login Caveat

OAuth callback URLs point to `BETTER_AUTH_URL` (default: `http://localhost:3001`). In dev, social login only works when the app is accessed on port **3001** (the backend), not Vite's `:3000` dev server.
